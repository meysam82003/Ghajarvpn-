# نسخه هدف 1.1.1 — فاز اول رفع باگ

شاخه کار: `work/1.1.1-phase1`.

## قواعد ادامه کار

تا پایان همه فازها Build اپ، GitHub Actions، PR به main، تگ و Release اجرا/ایجاد نشود.
تنها در پایان ارتقا و با درخواست کاربر یک Build/CI کامل برای 1.1.1 انجام شود.
نسخه و versionCode فعلاً همان 1.0.10 / 30025 باقی مانده‌اند.
هیچ تغییری از نسخه مبنا revert نشده است. backend و Mini App تغییر نکرده‌اند.

## علت و اصلاح ناوبری

`extraPage = conn:general` در هر دو کلید نمایش (`screenKey` و `setKey`) بر
`perAppDetail` و `logsDetail` اولویت داشت. کلیک فقط فلگ فرزند را روشن می‌کرد؛
Back ابتدا extraPage را پاک می‌کرد و تازه فرزند دیده می‌شد.
اولویت نمایش و Back برای این دو فرزند هماهنگ شد؛ با کلیک فوراً صفحه فرزند
نمایش داده می‌شود و Back به صفحه والد برمی‌گردد. هیچ delay یا refresh اضافه نشده است.

میان‌بر پروکسی برنامه‌ها و اشتراک VPN در بالای گروه اتصال تنظیمات قرار گرفت.
اشتراک VPN با نماد سپر در نوار ابزار انتخاب سرور نیز قرار گرفت.
هر دو مسیر اشتراک، همان VpnShareDialog و تنظیمات/عملکرد موجود را استفاده می‌کنند.

## علت و اصلاح هشدار قیمت

منبع فعلی `service_renew_options` فیلد `fx_quote.product` و `fx_quote.custom` را
برمی‌گرداند، اما مدل Android آنها را حذف می‌کرد و `service_renew_confirm`
بدون `fx_quote` ارسال می‌شد. سرور درخواست بدون توکن معتبر را پیش از کسر وجه
با 409 / `price_changed` رد می‌کند؛ همگام بودن مبلغ به تنهایی کافی نیست.
علت اثبات‌شده، حذف توکن قرارداد API بود؛ مشکل cache یا Float فرض نشده است.

قیمت و توکن از همان endpoint تازه دریافت می‌شود؛ قیمت انتخاب ثابت کاربر با
قیمت تازه مقایسه می‌شود. تغییر توکن به تنهایی هشدار قیمت ندارد. تغییر واقعی
مبلغ (کاهش یا افزایش) به تأیید مجدد نیاز دارد. پاسخ ساخت‌یافتهٔ 409 حفظ شده است.
اگر پس از تازه‌سازی، سرور توکن را با همان مبلغ رد کند، فقط یک بار با توکن
برگشتی دوباره اقدام می‌شود. تغییر مبلغ در این فاصله بدون تأیید کاربر پذیرفته نمی‌شود.
سایر خطاها و قطع ارتباط باعث تکرار خودکار درخواست تمدید نمی‌شوند.

مبالغ تمدید از رشته به BigDecimal و Long تبدیل می‌شوند؛ واحد همان تومان قرارداد
سرور است، بدون تبدیل ریال/USDT و بدون مقایسهٔ Float/Double. نمایش موجودیِ کسری
تومان به پایین گرد می‌شود؛ تصمیم پرداخت همچنان بر عهدهٔ سرور است.

## بازبینی جریان تمدید

- نام فیلد تمدید دلخواه از `traffic_gb` به `custom.volume_gb` مطابق سرور اصلاح شد.
- برای زمان ثابت، مقدار `min_time_days` ارسال می‌شود؛ پیش‌تر ورودی پنهان به صفر تبدیل می‌شد.
- مبلغ دلخواه با نرخ‌ها، تخفیف و گام گردکردن پاسخ سرور محاسبه و نمایش داده می‌شود.
- محدودیت حجم/زمان و موجود بودن پلن پیش از ارسال با پاسخ تازه کنترل می‌شود.
- انتخاب‌ها در حین درخواست ثابت می‌مانند؛ کلیک تکراری هم مسدود است.
- پلن فعلی، مصرف، باقی‌مانده، انقضا و وضعیت همچنان از مسیر اصلی service و
  CurrentServiceSummary نمایش داده می‌شوند؛ منطق آنها تغییر نکرد.
- کسری کیف پول و balance_after حفظ/خوانده می‌شوند؛ خطای قیمت با خطای موجودی مخلوط نمی‌شود.
- هیچ درخواست تمدید واقعی یا پرداختی برای تست ارسال نشده است.

## بررسی‌ها و محدودیت تأیید

۱۷ تست JUnit روی فایل واقعی GhajarRenewal.kt با کامپایلر مستقل Kotlin اجرا و همگی پاس شدند:
قیمت همگام، افزایش/کاهش، تأیید مجدد، توکن منقضی با همان مبلغ، تغییر نرخ هنگام تأیید،
محدودیت retry، قطع ارتباط، شکست دریافت قیمت، لغو coroutine، حذف پلن، کسری موجودی،
دقت پول، زمان ثابت، تخفیف/گردکردن دلخواه، ورودی خارج محدوده و قیمت مخفی/FX خاموش.

پنج فایل Kotlin تغییرکرده با PSI parser بررسی نحوی شدند و git diff --check پاس شد.
این بررسی‌ها جایگزین کامپایل کامل Android، تست Compose یا تست روی گوشی نیستند؛
این موارد طبق درخواست کاربر به فاز نهایی موکول‌اند. هیچ Gradle/Android Build،
GitHub Actions، APK، تگ یا Release در این فاز ایجاد نشده است.

مرجع READ-ONLY قرارداد: فایل پیوست ghajar-bot-v18-trust-tick-shop-report.zip،
ServiceRenewOptionsHandler.php، ServiceRenewConfirmHandler.php و pricing_fx.php.
