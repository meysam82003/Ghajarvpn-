# Engine runtime tests

What was actually run, where, and what it proved. "Not device verified"
means exactly that: nothing below ran on an Android phone.

## 1. Off-device, against the real pinned binaries (2026-09-26)

Environment: Linux x86-64 container. sing-box built from the pinned commit
(8330820, same build tags as CI, `CGO_ENABLED=0`); dnstt client/server built
from v1.20260501.0. The configs under test were produced by the app's own
Kotlin code (`ConfigParser` → `SingBoxConfig` → `DnsttRunner.args`), compiled
with kotlinc 2.2.10, not written by hand.

`curl` was run with `no_proxy` cleared: the container's `no_proxy` lists
127.0.0.1, and a first run that did not clear it silently bypassed the proxy
and "succeeded" for a wrong password. Those results were discarded; the
negative control is what caught it.

### 1a. `sing-box check` on generated configs

| Profile | Result |
|---|---|
| tuic:// (bbr, native UDP relay, h3) | accepted |
| hysteria:// v1 (auth, obfs, up/down) | accepted |
| anytls:// (uTLS chrome) | accepted |
| ssh:// with host key | accepted |
| openconnect:// fortinet, insecure | accepted |
| snell v4 (obfs tls) | accepted |
| snell v6 | accepted |
| negative control: unknown inbound type | rejected, exit 1 |

### 1b. Traffic end to end

Local sing-box servers (self-signed TLS) + client config generated by the app
+ HTTP request through the client's SOCKS5 port to a local HTTP server; success
counted only when the HTTP server logged the request.

| Chain | Result |
|---|---|
| AnyTLS | carried (`ghajar-e2e-ok`) |
| TUIC v5 | carried |
| Hysteria v1 (with obfs) | carried |
| Snell v6 | carried |
| AnyTLS, **wrong password** | nothing carried; server logged `anytls: authentication failed` |
| dnstt (UDP) → SOCKS5 upstream, via sing-box | carried; dnstt-server logged session + stream |
| dnstt, **wrong server key** | nothing carried; zero requests reached the HTTP server |

Not exercised end to end: SSH (no sshd in the container), OpenConnect (no
AnyConnect server), DoT/DoH dnstt transports.

## 3. On device — to do

Nothing here is claimed until run on a phone:

1. Import each new link type; connect; confirm `CONNECTED` only after the
   engine test succeeds; open a site.
2. Kill `libsingbox.so` / `libdnstt.so` mid-session → the session must end
   (not stay "connected").
3. Wi-Fi ↔ mobile switch while connected.
4. Android 11+ netlink restriction: sing-box must start without
   `auto_detect_interface` (tolerated per `route/network.go`).
5. Per-app mode ALLOWLIST with the app not listed: subprocess sockets must not
   loop into the tun.
