# GhajarVPN 1.0.3

روی ۱.۰.۰، ۱.۰.۱ و ۱.۰.۲ نصب می‌شود؛ با همان کلید امضا شده و کانفیگ‌هایت پاک
نمی‌شوند. `versionCode` از ۳۰۰۱۷ به ۳۰۰۱۸ رفته است.

این نسخه شش ایرادِ گزارش‌شده را برمی‌دارد و یک قابلیت اضافه می‌کند. یکی از آن شش
تا برنامه را می‌بست.

---

## ۱. کرش صفحهٔ پشتیبانی

| | |
| --- | --- |
| **چه می‌شد** | در فروشگاه، زدن روی «پشتیبانی» برنامه را کامل می‌بست |
| **چرا** | این صفحه داخل یک آیتم از لیست فروشگاه کشیده می‌شود و لیست، بچه‌هایش را با ارتفاع بی‌نهایت اندازه می‌گیرد. صفحه هم خودش را داخل یک ستونِ اسکرول‌شونده پیچیده بود، و یک اسکرول زیر ارتفاعِ بی‌نهایت، همان‌جا موقع اندازه‌گیری خطا می‌دهد |
| **چه شد** | اسکرول داخلی حذف شد؛ لیست زیرش از قبل اسکرول می‌شود |

بقیهٔ اسکرول‌های فروشگاه بررسی شدند: همه داخل دیالوگ هستند و ارتفاع کراندار
دارند. فقط همین یکی این شکلی بود.

## ۲. ویجت‌ها

**لوگوی اشتباه.** ویجت تک‌خانه‌ای `logo.png` را می‌کشید — نشانِ نوشتاری یک پروژهٔ
دیگر («GROUTE») که در سورس باقی مانده بود. یعنی روی صفحهٔ اصلی گوشیِ صاحب برنامه،
برند یک نفر دیگر. حالا هر دو ویجت نشان مربعِ خود قاجار را می‌کشند. نشانِ طلایی
عرض به ارتفاعش سه به یک است و در یک خانهٔ مربع تا هیچ کوچک می‌شد؛ برای همین
نشانِ مربع.

**«سروری انتخاب نشده» روی گوشی‌ای با ۲۷ سرور.** این ایراد واقعی بود:

| | |
| --- | --- |
| **چرا** | لیست کانفیگ‌ها در یک کوروتین از دیسک خوانده می‌شود. ویجت دقیقاً در همان لحظه‌هایی تازه می‌شود که این خواندن هنوز تمام نشده — بوت، نصب دوباره، یا پروسه‌ای که سیستم همین الان برای رساندن یک برودکست ساخته |
| **چه شد** | آخرین نامی که واقعاً پیدا شده بود به یاد می‌ماند، و به‌محض آمادگی انباره دوباره کشیده می‌شود |
| **دکمه‌ها** | هر سه دکمهٔ پینگ، آپدیت ساب و سرویس بعدی هم منتظر انباره می‌مانند. کار نکردنشان همین بود: روی لیستِ خالی عمل می‌کردند |

وضعیت، دکمهٔ روشن/خاموش و چراغ هیچ‌وقت کش نمی‌شوند؛ آن‌ها از `VpnState` می‌آیند
که از همان لحظهٔ اول درست است.

## ۳. «خوندم» روی اعلان

اعلان نشان داده می‌شد، ولی جوابی برایش وجود نداشت. کنار زدنِ اعلان از نوار
اعلانات به سرور چیزی نمی‌گوید، پس همان اخطارِ تکرارشونده دوباره سراغ کسی می‌آمد
که خوانده و اقدام هم کرده بود.

| کجا | چه اضافه شد |
| --- | --- |
| نوار اعلانات | دکمهٔ **خوندم** روی خود اعلان. اپ باز نمی‌شود؛ یک رسیور پیام را به فروشگاه می‌رساند و پروسه را تا پایانِ رفت‌وبرگشت باز نگه می‌دارد |
| نوار شناور داخل اپ | به‌جای ضربدرِ خالی، دکمهٔ «خوندم» با نوشته |
| مینی‌اپ | همان دکمه کنار دکمهٔ عمل اعلان |
| هر سه | دنبال کردنِ اعلان (مثلاً زدن «تمدید») هم یعنی خواندنش |

یک‌بار «خوندم»، و اعلان نه در اپ برمی‌گردد نه در مینی‌اپ — چون علامت روی حساب
ثبت می‌شود، نه روی این گوشی.

## ۴. ادامهٔ پرداخت

دو ایراد جدا بودند:

**دیده نمی‌شد.** کارتِ «ادامهٔ پرداخت» فقط زیر تب خرید و تب کیف پول کشیده می‌شد،
یعنی از چهار جای دیگرِ فروشگاه نامرئی بود. پولی که قبلاً درگیر شده، فوری‌ترین چیز
روی این صفحه است از هر جایی که ایستاده باشی — حالا از همهٔ تب‌ها دیده می‌شود.

**حسابش را گم می‌کرد.** سفارشِ بازسازی‌شده `username` نداشت، پس خریدی که بعد از
ادامه دادن تمام می‌شد، روی یک نام خالی تحویل می‌گرفت. حالا نام کاربری از سابقهٔ
خودِ سرور برای همان سفارش خوانده می‌شود. شارژ کیف پول نامی ندارد و لازم هم ندارد؛
پول در کیف می‌نشیند.

## ۵. خروج از حساب فروشگاه (تازه)

بعد از وصل شدن این گوشی به یک حساب، راهی برای بیرون آمدن نبود — کد اتصال یک‌طرفه
است. هر کسی که حساب اشتباه را وصل کرده بود، برای همیشه با آن می‌ماند.

| پاک می‌شود | می‌ماند |
| --- | --- |
| توکن حساب | سرورها و کانفیگ‌های روی گوشی |
| صندوق اعلان‌ها | اتصال فعلی (قطع نمی‌شود) |
| دفترِ تحویل سرویس‌ها | سرویس‌هایی که تا امروز تحویل گرفته‌ای |
| فاکتور ذخیره‌شدهٔ پرداخت | |

صندوق اعلان و دفتر تحویل با هشِ توکن کلید می‌خورند، پس اگر می‌ماندند حساب بعدی
علامت‌های «قبلاً دیده شد» و «قبلاً نصب شد» حساب قبلی را به ارث می‌برد و اعلان‌ها و
اولین تحویلِ خودش را بی‌صدا از دست می‌داد.

**کانفیگ‌ها عمداً دست نمی‌خورند.** خروج از یک فروشگاه نباید سروری را که داری
استفاده می‌کنی از تو بگیرد.

## نیازمندی سمت فروشگاه

«خوندم»، اعلان‌های کرون و کلید روشن/خاموش فروشگاه به نسخهٔ جدید فایل‌های ربات
نیاز دارند. ستون‌های `force_app_*` حالا اگر نباشند **خودشان ساخته می‌شوند** — چه
از سمت ربات چه از سمت API — پس «اجبار استفاده از اپ» دیگر بی‌صدا خاموش نمی‌ماند.
این دقیقاً همان ایرادی بود که باعث می‌شد آن قابلیت هیچ کاری نکند: نوشتن روی
ستونی که وجود نداشت، و خواندنی که همیشه «خاموش» برمی‌گرداند.

تا وقتی فایل‌های ربات آپلود نشده‌اند، اپ به رفتار قبلی برمی‌گردد و چیزی خراب
نمی‌شود.
