# Feature decisions

All mandatory audit columns are retained in FEATURE_MATRIX.json. This table is a readable view; decisions are future integration recommendations.

| ID | Feature | Layer | Current support | Decision | Reason |
|---|---|---|---|---|---|
| F001 | Verified on-demand Android plugin host | Plugin architecture | No external signed plugin registry; helpers bundled | MERGE_FEATURE | Use signed APK/nativeLibraryDir capabilities with ABI/core API constraints, hash/version pin and explicit install. Never allow custom-authority prefix to bypass signing checks. Do not remove working bundled engines. |
| F002 | sing-box registry extension architecture | Core architecture | Official executable plus sidecars already isolates gomobile runtime | BUILT_IN | Husi uses official sing-box alpha.8 plus registry extensions. TrustTunnel does not require adopting an entire sing-box fork. |
| F003 | Hysteria2 port hopping | Protocol-specific configuration | HY2 single-port Xray config; hopping fields not persisted/emitted | MERGE_FEATURE | Preserve port list/range and interval through import/editor/export; route to a core whose pinned schema supports it. Avoid a second HY2 protocol label. |
| F004 | Juicity | Protocol | Dedicated sidecar already available | BUILT_IN | Same gitlink as current Husi Juicity plugin; keep lifecycle/config checks, no duplicate Rust/Go engine. |
| F005 | Mieru | Protocol | ghajar-helper imports Mieru URL | BUILT_IN | Review server-port and auth configuration parity without adding a second client runtime. |
| F006 | ShadowQUIC | Protocol + optional plugin | Absent; ShadowTLS is separate | ON_DEMAND_PLUGIN | Use actual Husi plugin pin 5540e3a (v0.4.0), not similarly named older fork. Native lifecycle, protected sockets, binary signature and server compatibility gates required. |
| F007 | NaiveProxy | Protocol | sing-box naive outbound; Cronet build dependency | BUILT_IN | Standalone plugin only if native packaging or required options cannot be served by existing Cronet path; do not double Chromium footprint. |
| F008 | AnyTLS session settings | Protocol-specific configuration | Password/TLS supported; idle interval, timeout, minimum sessions absent | MERGE_FEATURE | Preserve typed idle_session_check_interval, idle_session_timeout, min_idle_session with validation. |
| F009 | TUIC advanced settings | Protocol-specific configuration | UUID/password/congestion/UDP mode supported | MERGE_FEATURE | Compare zero_rtt_handshake, udp_over_stream and idle timeout. Keep secure defaults; do not enable replay-sensitive 0-RTT automatically. |
| F010 | MASQUE CONNECT-IP | Protocol over HTTP transport | Generic sing-box masque-client endpoint plus Aether WARP | BUILT_IN | Distinguish generic authenticated MASQUE endpoint from Cloudflare WARP registration and nesting. |
| F011 | ECH options per protocol | TLS method | Xray echConfigList exists; MASQUE sing-box builder omits ECH | MERGE_FEATURE | Carry ECH configuration/query source only where pinned endpoint supports it; not a global claim for all engines. |
| F012 | uTLS fingerprint | TLS method/library | Existing Xray and selected sing-box TLS builders | BUILT_IN | Do not expose uTLS as VPN protocol; preserve compatible per-engine fingerprints. |
| F013 | OpenConnect enterprise authentication | Protocol-specific UI/auth lifecycle | Six flavors, auth group, client certificate/key, pin supported | MERGE_FEATURE | Review SSO/external-browser authentication, CA and MCA certificate options. Username/password alone is not full enterprise authentication parity. |
| F014 | OpenVPN import/auth settings | Config parser / UI | Dedicated OpenVPN module already present; sing-box tag also compiled | MERGE_FEATURE | Compare inline cert/key, tls-crypt-v2, auth challenges and validation; keep existing dedicated route, avoid switching engines merely for parity. |
| F015 | Full Mihomo providers/rules/config engine | Core / config semantics | Only Clash node import; providers and rules not preserved as full engine config | ON_DEMAND_PLUGIN | Keep entire validated Mihomo config under optional core adapter; exact vendored tree matters because constant.Version is blank and go.mod uses local replacement. |
| F016 | Mihomo TUN / MIPStack | tun2socks/network stack | zeptun owns TUN in Ghajar | SKIP | Do not start two VPN/TUN owners. Optional Mihomo can use local SOCKS or an explicitly exclusive TUN adapter. main and release 1.19.3 differ in auto stack selection. |
| F017 | Mihomo OpenVPN outbound | Protocol implementation | Existing dedicated OpenVPN and sing-box build flag | SKIP | Real implementation exists in vendored adapter/transport; useful inside optional full Mihomo configs, no separate additional VPN menu item. |
| F018 | Flutter platform plugins | UI/platform bridge | Native Kotlin app | NOT_APPLICABLE | Bettbox Flutter plugins are platform bridges, not proof of Husi-style externally installable protocol plugins. |
| F019 | TCP + UDP through SOCKS5 | tun2socks engine | Existing JNI/external fd configuration | BUILT_IN | SOCKS5 UDP availability depends on outbound; never present zeptun as VPN protocol. |
| F020 | ICMP forwarding vs local handling | Network stack behavior | Default SOCKS handler, not arbitrary ICMP tunnel | BUILT_IN | config.icmpForward(auto) is true only for direct handler. Local echo handling is not proof remote ICMP traverses SOCKS5. |
| F021 | Fake-IP and DNS hijack | DNS method | Conditional DNS section and Fake-IP configured | BUILT_IN | Keep Fake-IP mappings/routing lifecycle coupled; no new DNS protocol label. |
| F022 | Android package routing / protected sockets | Engine/platform routing | VpnService package rules and existing protection path | BUILT_IN | Upstream include/exclude packages and Android users are engine configuration; retain one owner of allow/exclude policy. |
| F023 | Performance/memory/size | Engine implementation | Mobile preset with 64 MiB budget configured | BUILT_IN | Budget is a cap, not measured resident memory. Upstream benchmarks do not prove phone throughput, battery or APK gain; defer device measurements. |
| F024 | MASQUE HTTP/3 | Transport/method on Aether core | Arguments wired in current app | BUILT_IN | Default MASQUE transport. No new core copy required. |
| F025 | MASQUE HTTP/2 | Transport/method on Aether core | Arguments wired in current app | BUILT_IN | --h2 and conditional H2 fragmentation. No new core copy required. |
| F026 | WireGuard | Transport/method on Aether core | Arguments wired in current app | BUILT_IN | --wg. No new core copy required. |
| F027 | WARP-in-WARP | Transport/method on Aether core | Arguments wired in current app | BUILT_IN | --gool plus WiW peer/scan settings. No new core copy required. |
| F028 | MASQUE-in-MASQUE | Transport/method on Aether core | Arguments wired in current app | BUILT_IN | --mim supported in AetherSpec; OblivionOptions has only masque/wg/gool. No new core copy required. |
| F029 | Route discovery | Transport/method on Aether core | Arguments wired in current app | BUILT_IN | --scan and --exit-loc; country route discovery is not guaranteed exit location. No new core copy required. |
| F030 | Tor-only / WARP→Tor / Tor→WARP | Chaining method / optional dependency | Separate Tor exists, native Aether Tor feature disabled | MERGE_FEATURE | Prefer orchestrating existing Tor with explicit direction/lifecycle where possible; enabling Aether tor feature adds dependency/size and requires separate validation. |
| F031 | Certificate verification and TLS options | Security configuration | SSTP TLS defaults to verified, pin supports explicit self-signed trust | SKIP | Do not copy upstream false verification defaults or plaintext preference passwords. TLS-version option changes must preserve certificate/hostname validation. |
| F032 | SSTP HTTP proxy | Transport option | Helper tls.DialWithDialer connects directly; no HTTP CONNECT option | MERGE_FEATURE | Add only if next phase requests it: authenticated CONNECT transport with separate proxy/server TLS identities and protected socket lifecycle. |
| F033 | SSTP custom DNS | DNS setting | Helper --dns fallback and current tunnel DNS policies exist | MERGE_FEATURE | Review settings propagation and server DNS precedence without globally overwriting other protocols. |
| F034 | Mahsa closed config/auth distribution | Closed service integration | Not present | SKIP | README declares config encryption and Mahsa authentication closed. No service credentials, closed source or release binaries copied. NikaNG does not establish parity with current releases. |
| F035 | Conduit / INPROXY | Psiphon mode | Explicitly disabled: missing ServerEntrySignaturePublicKey; selection probabilities zero | SKIP | Public Mahsa code selects INPROXY protocol names. Do not invent a separate core or enable it without legitimate prerequisites and a compatible verified Psiphon build. |
| F036 | Psiphon CDN fronting and chaining | Anti-censorship / chain method | CDN IP/SNI and Aether→Psiphon chain present | MERGE_FEATURE | Compare typed settings and chain readiness; no transplant of sponsor/service secrets. Transport exclusions in existing chain are intentional. |
| F037 | xDNS finalmask | DNS transport/mask | Existing DNS sidecars are not equivalent to xDNS finalmask | MERGE_FEATURE | Source exists: UDP PacketConn wrapping with resolver/domain framing. Not an ordinary DoH setting. Require bounded parsing, authenticated enclosing protocol, cancellation and IPv6/MTU tests before integration. |
| F038 | dnstt inside Xray | Transport adapter | Pinned dnstt sidecar already exists | SKIP | dialer.go uses unsynchronized package-level globalTunnel with no per-profile ownership visible. Avoid copying adapter; keep isolated existing sidecar. |
| F039 | DNS scanner | Diagnostic UI/method | DNS tunnel settings and probes exist; complete scanner parity unproven | MERGE_FEATURE | DNS scanner layout exists, but no controller/activity implementation was located in the public source snapshot; parity is unproven. Independently implement only after specifying behavior. Use DNS response validation, timeouts and bounded probes; never infer tunnel support from ping. |
| F040 | XHTTP / SplitHTTP | Transport | Xray builder handles xhttp/splithttp | MERGE_FEATURE | Compatibility aliases are not separate protocols. Preserve current compatible configs and migrate only proven deltas. |
| F041 | QUIC | Transport library | Multiple QUIC implementations inside existing engines | MERGE_FEATURE | Generic QUIC transport schema differs from HY2/TUIC/MASQUE; do not replace with a historical bring-quic-back branch. Preserve current compatible configs and migrate only proven deltas. |
| F042 | WireGuard + UDP Noise | Protocol plus anti-censorship method | WireGuard and configurable UDP noise exist | MERGE_FEATURE | Fork-specific wnoise/fake-host/finalmask schemas are not automatically compatible. Preserve current compatible configs and migrate only proven deltas. |
| F043 | Hysteria2 | Protocol | Xray Hysteria version 2 configuration | MERGE_FEATURE | Port hopping is tracked separately. Preserve current compatible configs and migrate only proven deltas. |
| F044 | DoH | DNS method | Xray DNS configuration and DNS tunnel resolver options | MERGE_FEATURE | DNS encryption differs from carrying arbitrary traffic inside DNS. Preserve current compatible configs and migrate only proven deltas. |
| F045 | Fragmentation / fake host | Anti-censorship method | Existing fragmentation and host/SNI config | MERGE_FEATURE | Compare exact fragment/finalmask fields against pinned core; no global guarantee against DPI. Preserve current compatible configs and migrate only proven deltas. |
| F046 | Free config systems | Subscription/data parser | Subscriptions supported | MERGE_FEATURE | Reuse normalization/deduplication concepts only with opt-in sources, bounded payloads and scheme/field validation. Public aggregation is not trust or uptime evidence. |
| F047 | Wrong-sequence packet injection | Anti-censorship method | No WinDivert/root injection in Android app | NOT_APPLICABLE | pydivert and WinDivert require Windows packet interception; ordinary rootless Android VPN cannot simply call this implementation. |
| F048 | Direct fragment presets | Config generator / method | Existing Xray fragment config | MERGE_FEATURE | Validate generated templates against exact Xray schema; this is not arbitrary traffic serverless VPN or a new protocol. |
| F049 | Tor/Psiphon/WARP chain controller | UI/lifecycle method | Aether→Psiphon supported; broader directions not all exposed | MERGE_FEATURE | Current v8-era source has Tor as separate core and both chain directions. Review readiness via real SOCKS request and teardown without duplicating VpnService. |
| F050 | Additional WARP executable | Core | Aether + Psiphon already provide required baseline | SKIP | Do not add another WARP binary just to increase option count; only specific non-overlapping fixes merit a merge. |
| F051 | smartSNI DNS substitution | DNS/server method | Existing DNS methods differ | SKIP | Source serves DNS/TLS; missing root license plus pooled-buffer response lifetime and loose substring matching make verbatim adoption unsuitable. |
| F052 | Psiphon binary/source reproducibility | Core maintenance | AAR has local (devel) replacement; source comparison has local deltas | UPDATE_EXISTING | Record source commit, patches and all local QUIC/DTLS/qpack replacements before next authorized build. Preserve local fixes; version strings alone cannot prove binary provenance. |
| F053 | Xray prerelease migration assessment | Core update candidate | Latest non-prerelease embedded; 705 changed paths to inspected main | UPDATE_EXISTING | Candidate only: gate schema migration, XHTTP/finalmask/ECH/QUIC behavior, gomobile APIs and protocol regression tests. No update performed and no stable downgrade/revert. |
