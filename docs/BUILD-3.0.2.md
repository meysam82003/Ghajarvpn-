# ۳.۰.۲ — اتصال ربات، معماری هسته و امضای دمو

## ورود به حساب

- دکمهٔ اتصال و خود عدد کد، ابتدا `tg://resolve?domain=Ghajar_vpnbot&start=link_123456`
  را باز می‌کنند؛ مسیر وب جایگزین، همان `start` را حفظ می‌کند.
- کد نامعتبر یا منقضی‌شده هرگز به بازکردن چت بدون فرمان تبدیل نمی‌شود.
- در تلگرام، کاربر باید **Start / شروع** را بزند. سپس ربات فرمان
  `/start link_123456` را می‌گیرد؛ نوشتن یا ویرایش کد لازم نیست.
  این تأیید بخشی از [قرارداد رسمی تلگرام](https://core.telegram.org/api/links#bot-links)
  است و برنامه آن را به‌جای کاربر اجرا نمی‌کند.
- کد، توکن موقت و مهلت اولیه قبل از رفتن به تلگرام با AES-GCM و Android Keystore
  ذخیره می‌شوند. بازسازی صفحه یا بسته‌شدن فرایند، زمان کد را تمدید نمی‌کند.
- توکن موقت هنگام اتصال موفق، خروج از حساب یا انقضا پاک می‌شود.
- مسیر پردازش ربات با ZIP کامل ارسالی (`re/rx/index/bootstrap.php` و
  `api/lib/WebLink.php`) تطبیق داده شد؛ هیچ تغییر یا استقرار زنده‌ای روی سرور ربات انجام نشده است.

## اصلاح OpenSSL

منبع پین‌شدهٔ OpenSSL: `schwabe/platform_external_openssl`، کامیت
`e0115652413ba9eef1f2847e2ad7a5c8f360aabd`.
[فهرست رسمی معماری‌ها](https://github.com/schwabe/platform_external_openssl/blob/e0115652413ba9eef1f2847e2ad7a5c8f360aabd/crypto/ec/build.info)
فایل `ecp_sm2p256.c` را برای ARM64 به‌همراه اسمبلی آن انتخاب می‌کند، ولی فایل
CMake این نسخه آن را برای همهٔ معماری‌ها فهرست کرده است.

گارد قاجار، همین فایل بهینه‌شده را فقط برای ARM64 نگه می‌دارد؛ پیاده‌سازی عمومی
SM2، الگوریتم‌های رمزنگاری و بررسی گواهی‌ها تغییر نمی‌کنند. هشدارهای
`fortify-source` در هدف OpenSSL به خطای ساخت تبدیل شده‌اند. تست‌های CMake چهار
ABI و چهار پیکربندی نامعتبر را کنترل می‌کنند؛ این تست انتخاب سورس است، نه تست
اتصال روی چهار نوع گوشی.

## چرا APKهای قبلی روی هم نصب نمی‌شدند؟

رانر تازهٔ CI کلید debug تازه می‌سازد. APKهایی که گواهی امضای یکسان ندارند،
به‌روزرسانی یکدیگر نیستند. کلید خصوصی را نمی‌توان از APK بازیابی کرد.
[راهنمای امضای اندروید](https://developer.android.com/studio/publish/app-signing)

ساخت خودکار PR برای تست است و در نام خروجی `CI-ephemeral-key` دارد. برای دموهای
قابل‌به‌روزرسانی، یک کلید خصوصی **مخصوص دمو** را یک‌بار ایجاد و امن نگه دارید؛
از کلید انتشار نهایی استفاده نکنید. کلید یا رمزها نباید وارد مخزن، لاگ، PR،
فایل‌های خروجی یا چت شوند.

در Settings → Secrets and variables → Actions این چهار Secret لازم‌اند:

| Secret | مقدار |
| --- | --- |
| `GHAJAR_DEMO_KEYSTORE_B64` | محتوای Base64 فایل keystore خصوصی دمو |
| `GHAJAR_DEMO_KEYSTORE_PASSWORD` | رمز فایل |
| `GHAJAR_DEMO_KEY_ALIAS` | نام کلید داخل فایل |
| `GHAJAR_DEMO_KEY_PASSWORD` | رمز همان کلید |

سپس Actions → Android CI → Run workflow، شاخهٔ `main` و گزینهٔ `signed_demo`
را انتخاب کنید. این مسیر اگر Secret یا فایل ناقص باشد متوقف می‌شود؛ هیچ کلید
موقت جایگزین نمی‌کند. ساخت PR به این Secretها دسترسی داده نمی‌شود.

کلید ثابت جدید، امضای دموهای قدیمی را بازسازی نمی‌کند؛ بنابراین نصب اول آن روی
دموهای قبلی همچنان به انتقال داده نیاز دارد. قبل از حذف هر نسخه، از داخل اپ
پشتیبان بگیرید. قابلیت نصب روی نسخهٔ قبلی فقط پس از دو ساخت با **همان کلید**
قابل تأیید است. در این مرحله هیچ Secret جدیدی در GitHub تنظیم نشده است.

## مرز تأیید

CI بازسازی پچ، تطابق سورس، آزمون‌های واحد، انتخاب معماری، ساخت دو APK و امضاهای
آن‌ها را بررسی می‌کند. تست گوشی، تلگرام واقعی، بازیابی پس از توقف فرایند، اتصال
VPN و پرداخت واقعی جداگانه لازم است. این نسخه هنوز دمو Android 8+ است.
