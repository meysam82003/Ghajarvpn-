# بازطراحی کامل UI/UX قاجار VPN

این سند مرجع طراحی است: ساختار صفحه‌ها، جای هر قابلیت، کدهای رنگ و ساختار تم،
و کارهایی که انجام نشده و دلیلش.

تنها چیزی که از هویت بصری قبلی نگه داشته شده **لوگوی قاجار VPN**
(`GhajarWordmark`) است. بقیهٔ ساختار از صفر ساخته شده.

---

## ۱. ساختار ناوبری

سه تب، نه بیشتر. ترتیب اعلان در کد از راست به چپ خوانده می‌شود، پس زیر RTL
نوار پایین این‌طور دیده می‌شود:

```
خانه  |  فروشگاه  |  تنظیمات
```

- `PAGE_HOME = 0` — صفحهٔ پیش‌فرض در هر اجرا و مقصد هر «بازگشت از همه‌جا»
- `PAGE_SHOP = 1`
- `PAGE_SETTINGS = 2`
- `PAGE_COUNT = 3`

SSH و دیباگر قبلاً تب بودند. همان صفحه‌ها با همان قابلیت‌ها الان از داخل
تنظیمات باز می‌شوند تا نوار سه‌تایی بماند.

## ۲. صفحهٔ خانه — دکمهٔ اتصال وسط

از بالا به پایین، همه وسط‌چین:

| ترتیب | جزء | کار |
|---|---|---|
| ۱ | `GhajarWordmark` | لوگو |
| ۲ | `ConnectOrb` | دکمهٔ دایره‌ای ۲۳۶dp وسط صفحه — وصل / قطع / لغو انتخاب خودکار |
| ۳ | `SessionLine` | مدت نشست جاری، فقط وقتی تونل بالاست |
| ۴ | `StatusLine` | وضعیت واقعی تونل + دو خطای مهم: اینترنت دستگاه قطع، تونل برقرار ولی بدون داده |
| ۵ | `Slab` + `SlabRow` | مسیر: سرور انتخاب‌شده، یک لمس تا انتخابگر |
| ۶ | `StatStrip` | دو خانه: سرعت دانلود و آپلود، با مجموع هرکدام زیرش |
| ۷ | `ConnectionFacts` | یک Slab با چهار ردیف: آی‌پی، کشور، پینگ زنده، و **تست تأخیر واقعی** (لمس = تست) |

نکته‌های فنی مهم:

- مقدارهای انیمیشن (`sweepState`, `breathState`) **فقط داخل لامبدای رسم
  `Canvas`** خوانده می‌شوند. کرهٔ قبلی همین را رعایت نمی‌کرد و باعث می‌شد کل
  زیردرخت هر فریم recompose شود.
- ستون وقتی جا شود وسط‌چین می‌ماند و وقتی جا نشود اسکرول می‌کند
  (`BoxWithConstraints` + `heightIn(min = maxHeight)` + `verticalScroll`)، پس
  صفحهٔ کوتاه یا فونت بزرگ سیستم هیچ‌وقت چیزی را نمی‌برد.
- هالهٔ نورانی فقط در حالت متصل کشیده می‌شود؛ صفحهٔ بی‌کار هیچ انیمیشنی ندارد.

## ۳. جای هر قابلیت بعد از بازطراحی

### قابلیت‌هایی که از خانه جابه‌جا شدند

| قابلیت قبلی | کجا بود | الان کجاست |
|---|---|---|
| وصل شدن | نوار تمام‌عرض پایین کارت | `ConnectOrb` وسط صفحه |
| قطع کردن | همان نوار | همان دکمه (آیکون و متن عوض می‌شود) |
| لغو انتخاب خودکار سریع‌ترین | همان نوار | همان دکمه |
| انتخاب/تغییر سرور | `GhajarSelectedServerCard` | ردیف مسیر (`SlabRow`) زیر دکمه |
| نام پاک‌سازی‌شدهٔ کانفیگ | همان کارت | ردیف مسیر (`BrandConfig.sanitizePublicText`) |
| مخفی‌ماندن اندپوینت کانفیگ قفل‌شده | همان کارت | ردیف مسیر |
| «موتور داخلی» برای aether/tor | همان کارت | ردیف مسیر |
| راهنمای OpenVPN وقتی سروری انتخاب نشده | همان کارت | زیرنویس ردیف مسیر |
| سرعت و مجموع دانلود/آپلود | `StatBox` | `StatStrip` دوخانه |
| تست تأخیر واقعی | دکمهٔ کنار `StatBox` | ردیف چهارم Slab فکت‌ها (لمس = تست) |
| تایمر نشست | داخل `ConnectionHub` | `SessionLine` |
| آی‌پی / کشور / پینگ | `HubFact` داخل `ConnectionHub` | `ConnectionFacts` (سه ردیف یک Slab) |
| رنگ خطای آفلاین و تونل مرده | نوار اتصال | `ConnectOrb` + `StatusLine` |

### تنظیمات (دسته‌بندی‌شده)

| دسته | ورودی‌ها |
|---|---|
| اتصال و سرورها | تنظیمات اتصال، ابزارها |
| عیب‌یابی و شبکه | دیباگر، رادار شبکه، SSH |
| مصرف داده | مصرف داده |
| برنامه | ظاهر برنامه، اعلان‌ها، درباره |
| داده‌های تو | پشتیبان‌گیری و بازیابی |

### ابزارها (دسته‌بندی‌شده)

| دسته | ورودی‌ها |
|---|---|
| اشتراک‌گذاری و تاریخچه | اشتراک‌گذاری VPN، تاریخچهٔ اتصال، لاگ و اشکال‌زدایی |
| اندازه‌گیری و تست | تست پایداری، بررسی میزبان، اسکن IP پاک |
| حریم خصوصی و مسیردهی | مسدودسازی تبلیغ (+ زیرتنظیم همیشه‌روشن)، مسیردهی پیازی، اتصال هوشمند |

### جابه‌جایی‌های دیگر

| قابلیت | قبلاً | الان |
|---|---|---|
| تنظیمات اعلان | بلوکی داخل بخش سوم فروشگاه | صفحهٔ «اعلان‌ها» در تنظیمات → برنامه |
| SSH | تب سطح‌اول | تنظیمات → عیب‌یابی و شبکه |
| دیباگر کانفیگ | تب سطح‌اول | تنظیمات → عیب‌یابی و شبکه |

هیچ قابلیتی حذف نشده و هیچ‌کدام تزئینی نشده. منطق اتصال، پروتکل‌ها، API
فروشگاه، پرداخت و بکاپ دست‌نخورده است.

## ۳.۵ زبان بصری «Slab» — پوستهٔ ساخته‌شده از صفر

پوستهٔ قبلی «هر عنصر یک کارت با حاشیه» بود؛ یک صفحه می‌شد پشته‌ای از جعبه‌های
خط‌دار یکسان، که یعنی فهرستی از چیزهای هم‌ارزش — یعنی هیچ. کنار گذاشته شد.
`GhajarSkin.kt` این پنج قاعده را دارد:

1. **یک Slab چند ردیف را نگه می‌دارد.** گروه کنترل‌های مرتبط یک سطح پرشدهٔ واحد
   با جداکنندهٔ تودرفته است، نه N کارت جدا.
2. **نور روی لبهٔ بالا می‌افتد.** هر Slab یک خط ۱ پیکسلی گرادیانی برند روی لبهٔ
   بالایش می‌کشد — روشن‌ترین در وسط، محو در گوشه‌ها — و هیچ جای دیگر.
3. **تیترها ریل‌اند.** میلهٔ عمودی کوتاه برند + برچسب + خطی تا لبهٔ صفحه.
4. **عددها در Strip زندگی می‌کنند.** یک Slab با خطوط عمودی نازک، چند خوانش در
   یک شیء، نه یک کاشی برای هر عدد.
5. **انتخاب‌شده سُر می‌خورد.** کنترل قطعه‌ای و نوار پایین، شناساگر پرشده را به
   خانهٔ فعال حرکت می‌دهند، نه این‌که خانه‌ها بازرنگ شوند.

### اجزای پوسته

ظرف و چیدمان: `Slab`، `SlabRow`، `SlabDivider`، `Rail`، `ScreenHeader`،
`StatStrip` + `StatCell`.

کنترل‌ها: `PillButton`، `GhostPill`، `GlyphTile`، `SkinSwitch`، `SkinField`،
`SlidingSegments`، `TabRail` + `RailTab`.

ناوبری و حالت‌ها: `SkinNavBar` + `SkinNavItem`، `SkinLoading`، `SkinEmpty`،
`SkinError`.

`StatCell` می‌تواند `onClick` داشته باشد؛ آن‌وقت خود عدد مقصد است و دیگر لازم
نیست زیر یک نوار آمار، ردیفی از دکمه‌ها همان برچسب‌ها را تکرار کند.

`TabRail` یک ردیف افقی اسکرول‌شونده از مقصدهاست که هر تب می‌تواند عدد خودش را
حمل کند. برای شش بخش فروشگاه ساخته شد، چون شش برچسب فارسی در یک
`SlidingSegments` خوانا نمی‌شود و دو کنترل سه‌تایی روی هم، دو ردیف کروم قبل از
اولین پلن می‌ساخت.

ردیف‌ها `mixedText()` را اعمال می‌کنند، پس تیتر فارسی که کلمهٔ لاتین داخلش دارد
(نام پروتکل، نام میزبان) برای هر اجرا فونت درست خودش را نگه می‌دارد.

### قاعدهٔ حاشیه

حاشیه فقط به معنای «این یک کنترل است»، نه «این یک جعبه است» — و از این پاس به
بعد حتی فیلد متن هم حاشیه ندارد. چیزهایی که حاشیه دارند: چک‌باکس، چیپ/نشانی که
یک مقدار نشان می‌دهد، `GhostPill`، قاب QR و کادر دوربین اسکنر. هیچ ظرفی حاشیه
ندارد.

### نقطهٔ واحد کنترل‌ها

سه تابع مشترک، شکل قدیمی را در همهٔ صفحه‌ها می‌کشیدند؛ عوض کردن همان سه تا،
همهٔ صفحه‌ها را عوض کرد:

- `SettingRow` → همهٔ ۲۰ کلید تنظیمات برنامه. حالا `SkinSwitch` را می‌کشد، یک
  کاشی آیکن اختیاری دارد و کل ردیف هدف لمس است، نه فقط خود کلید.
- `FillButton` → هر `BounceButton`/`BounceOutlinedButton`/`BounceTextButton`.
  حاشیهٔ مویی و بلور شیشه‌ای حذف شد؛ کپسول پرشده بدون خط ماند و پر شدن با رنگ
  تأکید هنگام فشار سرجایش. ضمناً «اصلی» و «فرعی» تازه از هم قابل تشخیص شدند:
  قبلاً فقط ۲dp در برابر ۱.۵dp ضخامت حاشیه فرق داشتند.
- `LabeledDropdown` → پروتکل، شبکه، امنیت، اثرانگشت، حالت و روش رمز. تا چهار
  گزینه ردیف چیپ است؛ بیشتر از آن منو می‌ماند ولی روی جعبهٔ پرشدهٔ پوسته.

دو کامپوننت متریال هم از راه `GhajarComposeCompat` — همان جایی که برنامه از قبل
برای `Surface` این کار را می‌کرد — با هم‌نام هم‌امضای خودشان جایگزین شدند، تا
لازم نباشد ۵۱ محل فراخوانی دستی ویرایش شود:

- `OutlinedTextField` (۴۰ محل): جعبهٔ پرشده، برچسب بالای جعبه، زیرخط برند هنگام
  فوکوس. پارامتر `shape` پذیرفته و عمداً نادیده گرفته می‌شود، چون دیگر خطی
  نیست که گردش کنیم.
- `AlertDialog` (۱۱ محل): ورقهٔ برجسته با نور لبهٔ بالا، سقف ارتفاع ۸۲٪ پنجره
  تا بدنه‌های اسکرول‌شونده هنوز کار کنند.

### نوار پایین

`NavigationBar` متریال حذف شد: شناساگرش سرجا محو می‌شد و سطحش روی بوم تقریباً
سیاه گم می‌شد (به همین دلیل پاس قبلی مجبور شده بود دور آن خط بکشد تا دیده شود).
`SkinNavBar` یک کپسول شناور روی تون کارت است با یک شناساگر پرشدهٔ برند که بین
سه مقصد سُر می‌خورد، هر سه برچسب همیشه دیده می‌شوند، و خودش inset نوار ناوبری
سیستم را رعایت می‌کند.

### دیالوگ‌ها

`GlassDialog` که جلوی تقریباً همهٔ دیالوگ‌های برنامه است، الان ورقهٔ پوسته است:
سطح برجسته با همان نور لبهٔ بالا (در رنگ تأکید دیالوگ)، تیتر روی یک ریل، و دو
عمل به‌صورت pill — تأیید پرشده، انصراف ghost. قبلاً هر دو عمل دکمهٔ خط‌دار
یکسان بودند، پس هیچ‌چیز نمی‌گفت کدام همان کاری است که برایش آمده‌ای.

## ۴. سیستم طراحی

همه‌چیز در `GhajarDesign.kt`. کامپوننت‌ها هیچ‌وقت رنگ عددی ندارند — بیرون از
این فایل و `Flagcolors.kt` (که رنگ پرچم ملی است، یعنی داده نه تم) هیچ فایلی
`Color(0x...)` ندارد.

### توکن‌های رنگ

`GhajarPalette` این‌ها را دارد: سطح‌ها (`background`, `surface`, `card`,
`secondaryCard`)، برند (`primary`, `premium`, `highlight`, `successGlow`)،
متن (`textPrimary`, `textSecondary`, `textMuted`)، خط (`border`,
`borderStrong`)، حالت‌ها (`error`, `onError`, `errorSurface`, `warning`,
`good`, `info`, `accentAlt`)، داده‌نما (`chart`, `neutralBar`)، و
(`disabled`, `onDisabled`, `scrim`).

معنی سه توکن که راحت اشتباه می‌شوند:

- `primary` = رنگ برند برای کارهای اصلی
- `good` = نتیجهٔ اندازه‌گیری سالم (پینگ سریع، تست موفق) — جدا از برند
- `successGlow` = فقط هالهٔ حالت «متصل»

### Premium Green Dark (پیش‌فرض نصب اول)

| نقش | کد |
|---|---|
| Background | `#050807` |
| Surface | `#0B1512` |
| Card | `#101816` |
| SecondaryCard | `#14231F` |
| PrimaryGreen | `#00A86B` |
| PremiumGreen | `#00B978` |
| HighlightGreen | `#24D98B` |
| SuccessGlow | `#0CE6A0` |

این هشت مقدار در `object GhajarBrand` یک‌جا تعریف شده‌اند؛ تم‌ها به آن‌ها
ارجاع می‌دهند و کامپوننت‌ها هیچ‌وقت.

### تم‌ها

چهار پالتهٔ کامل و مستقل، به‌علاوهٔ پیروی از سیستم:

1. `PREMIUM_GREEN_DARK` — پیش‌فرض نصب اول
2. `PREMIUM_GREEN_LIGHT` — سبزها تیره‌تر شده‌اند تا روی سفید کنتراست AA بدهند
3. `MIDNIGHT_BLUE`
4. `GRAPHITE_GOLD`
5. `SYSTEM` — بین دو پالتهٔ Premium Green سوئیچ می‌کند، پس پیروی از سیستم
   هویت برند را از دست نمی‌دهد

انتخاب در «تنظیمات → برنامه → ظاهر برنامه» است، در `ConfigStore` زیر کلید
`ui_theme` ذخیره می‌شود، از `ThemeMode` قبلی مهاجرت داده می‌شود، و فوراً
همه‌جا اعمال می‌شود.

### اضافه کردن تم جدید (سه قدم)

1. یک مقدار به `GhajarThemeId` اضافه کن (اسم را عوض نکن — اسم ذخیره می‌شود).
2. یک `GhajarPalette` کامل بساز؛ کامپایلر تا هر ۲۸ توکن پر نشود اجازه نمی‌دهد،
   پس تم نیمه‌کاره ممکن نیست.
3. در `GhajarPalettes` و `ghajarPaletteFor()` ثبتش کن.

هیچ صفحه‌ای لازم نیست عوض شود: `toColorScheme()` هر پالت را روی
Material 3 تصویر می‌کند، پس صفحه‌هایی که با `MaterialTheme.colorScheme`
نوشته شده‌اند هم خودکار تم فعال را می‌گیرند.

### فاصله، شعاع، حرکت

- `GhajarSpacing`: xs 4 · sm 8 · md 12 · lg 16 · xl 24 · xxl 32
- `GhajarRadius`: sm 10 · md 16 · lg 22 · xl 28 · pill 999
- `GhajarMotion`: Fast 140 · Base 220 · Slow 320 میلی‌ثانیه

### کامپوننت‌های مشترک

- `GhajarCard` (`GhajarCards.kt`) — **تنها تعریف کارت**: سطح کارت تم، خط مویی،
  شعاع md، بدون سایه. پارامتر `accent` فقط خط مویی را به رنگ حالت عوض می‌کند،
  پس کارت «در انتظار» شکلش عوض نمی‌شود.
- `SettingsHubCard`, `SettingsGroup`, `SettingsSectionTitle`, `GlassDialog`,
  `MetricTile`, `StatusLine`, `ServerPill`, `ConnectOrb`

### یک استثنای مستند

`object GhajarFixed` — QR باید با دوربین خوانده شود، پس جفت کنتراست ثابت دارد.
اگر تم را دنبال می‌کرد، در پالتهٔ روشن غیرقابل‌اسکن می‌شد.

## ۵. پنجره‌های غیر-Compose

دو پنجره از View ساخته شده‌اند (میزبان‌های WebView) و نمی‌توانند
`CompositionLocal` بخوانند، پس تا این بازطراحی با سرمه‌ای قدیمی `#071B2E`
رنگ می‌شدند:

- `GhajarStoreWebActivity` (پنل کامل فروشگاه)
- `SecurePaymentActivity` (مرورگر پرداخت امن)

تابع `ghajarPaletteFor(context)` همان تم ذخیره‌شده را بدون Compose حل می‌کند.
هر دو الان نوار وضعیت، نوار ناوبری، ظرف و پس‌زمینهٔ WebView را از پالتهٔ فعال
می‌گیرند و روشن/تاریک بودن آیکون‌های نوار وضعیت را از `palette.dark`
می‌خوانند.

**فلاش سفید هنگام اجرا:** پس‌زمینهٔ پنجره پیش از اجرای Compose توسط پلتفرم
کشیده می‌شود و روی پیش‌فرض Material Light بود، پس هر اجرای سرد یک فلاش سفید
داشت. الان به بوم برند اشاره می‌کند (`values-night/` نسخهٔ تاریک را دارد).

## ۵.۴ پاس اصلاح از روی اسکرین‌شات‌ها

پنج ایراد که روی دستگاه دیده شد و ریشهٔ هرکدام:

**درز دو‌رنگ بالای صفحه.** `CenterAlignedTopAppBar` هیچ `colors =` نداشت، پس
رنگ ظرف پیش‌فرض متریال را می‌کشید در حالی که صفحهٔ زیرش بوم برند را می‌کشید. در
تم روشن این اختلاف کاملاً دیده می‌شد و بالای صفحه مثل یک کادر جدا می‌نمود. حالا
ظرف و ظرفِ اسکرول‌شده هر دو شفافند و تنها چیزی که از نوار وضعیت به پایین کشیده
می‌شود، خودِ بوم Scaffold است. `BounceIconButton` هم کاشی برجستهٔ گرادیانی‌اش را
از دست داد، چون گوشهٔ یک هدر یک‌دست، همان درز را دوباره می‌کشید.

**بیرون‌زدن متن از دایرهٔ اتصال.** برچسب داخل orb با `maxLines = 1` و
`softWrap = false` داخل یک `Box` بدون قید عرض بود، پس رشتهٔ بلند صاف از روی
حلقه رد می‌شد. حالا ستون برچسب به مربع محاطِ دایره مقید است و تا دو خط با
ellipsis می‌شکند. رشتهٔ فارسی «در حال اتصال» هم دنبالهٔ «(برای لغو ضربه بزنید)»
را انداخت — ضربه همچنان لغو می‌کند، فقط برچسب دیگر توضیحش نمی‌دهد.

**دو لوگو، یک صفحه.** لوگوی کوچک زیر اپ‌بار، همان لوگوی بزرگ دو ردیف بالاتر را
تکرار می‌کرد. حذف شد.

**چیپ وضعیت زیر orb.** همان چیزی را می‌گفت که رنگ و برچسب خود orb می‌گوید. حذف
شد و `StatusLine` با آن.

**دو تا «پینگ».** `ConnectionFacts` ردیف `hub_ping` خودش را داشت و فراخوان هم
ردیف `real_delay` را اضافه می‌کرد؛ هر دو در فارسی «پینگ» می‌شوند. حالا یک ردیف
است: مقدار هندشیک غیرفعال را نشان می‌دهد و با ضربه، تست تأخیر واقعی را اجرا و
نتیجهٔ آن را جایگزین می‌کند.

## ۵.۶ کندی فروشگاه — سمت کلاینت

دو علت واقعی، جدا از سه علت سمت ربات که در بخش جداگانه آمده:

**هر درخواست، یک TLS handshake تازه.** `performRequest` در بلوک `finally` خود
`connection.disconnect()` صدا می‌زد. این سوکت را از استخر keep-alive بیرون
می‌اندازد، پس هر کدام از چند فراخوانی که فروشگاه را بار می‌کنند، هزینهٔ TCP و
TLS خودش را به همان میزبان می‌پرداخت. حالا فقط درخواستی که با خطا تمام شود
قطع می‌کند.

**۱۵ ثانیه انتظار بعد از پرداخت.** حلقهٔ بررسی وضعیت پرداخت روی تایمر ثابت
۱۵ ثانیه بود. این حلقه داخل `repeatOnLifecycle(RESUMED)` است، یعنی دقیقاً وقتی
کاربر از صفحهٔ پرداخت برمی‌گردد از نو شروع می‌شود؛ پس حالا از ۲ ثانیه شروع و
تا ۱۵ ثانیه عقب می‌نشیند، نه اینکه از ۱۵ شروع کند.

## ۵.۵ رفع کرش اتصال (۱۸ سپتامبر ۲۰۲۶)

از لاگ دستگاه:

```
SecurityException: Unable to launch app com.ghajarvpn.app/10666
  for service .../GozarVpnService: process is bad
```

«process is bad» یعنی ActivityManager بعد از کرش‌های تکراری آن پروسه را
علامت‌دار کرده و دیگر اجرایش نمی‌کند. این علامت تا Force stop، به‌روزرسانی
برنامه یا ری‌استارت دستگاه پاک نمی‌شود. کد قبلی فرض کرده بود «within a second
or two» پاک می‌شود و سه بار retry می‌کرد؛ لاگ این را رد می‌کند — دو اتصال جدا با
۱۴ ثانیه فاصله، هر دو رد شده.

`GozarVpnService` تنها جزئی بود که `android:process=":vpn"` داشت، پس هر اتصال
نیاز به اجرای همان پروسهٔ علامت‌دار داشت. دیگر پروسهٔ جدا اعلام نمی‌کند و در
پروسهٔ اصلی اجرا می‌شود — پروسه‌ای که کاربر خودش با باز کردن اپ اجرا کرده و تا
اپ باز است نمی‌تواند در آن وضعیت باشد.

این سطح خطر بومی جدیدی اضافه نمی‌کند: `gozarcore` از قبل در پروسهٔ اصلی لود و
اجرا می‌شد (`MainActivity` لاگرش را در startup وصل می‌کند و هر اندازه‌گیری تأخیر
صدایش می‌زند)، یعنی موتور هیچ‌وقت واقعاً از پروسهٔ UI جدا نبود.

سخت‌سازی تا علامت دوباره گذاشته نشود:
- `onCreate()` سرویس دیگر نمی‌تواند throw کند (throw در آن، ساخت سرویس را abort
  می‌کند و دو abort پشت‌هم دقیقاً همان چیزی است که علامت را می‌گذارد).
- هر اجرا ثبت می‌کند در کدام پروسه اجرا شده، تا لاگ بعدی اثبات کند نه استنباط.
- حلقهٔ retry بی‌فایده جایش را به یک retry برای رد گذرای واقعی و بعد پیامی داد
  که می‌گوید چه چیزی علامت را پاک می‌کند — قبلاً می‌گفت «مجوز VPN را بررسی کن»
  که گمراه‌کننده بود، چون مجوز هیچ‌وقت مشکل نبود.

روی دستگاه آزمایش نشده: CI نمی‌تواند VPN اجرا کند. چیزی که قطعی است مسیر
رد‌شده حذف شده، چون دیگر هیچ پروسهٔ جدایی اجرا نمی‌شود.

## ۷. حجم APK — عدد واقعی

از آرتیفکت‌های دیباگ CI، برای بخش UI این مأموریت:

| بیلد | حجم APK دیباگ | تغییر |
|---|---|---|
| CI 121 (قبل از حذف کره) | ۱۷۳٬۴۹۵٬۰۵۷ بایت | — |
| CI 123 (بعد از حذف ۱٬۷۵۳ خط کد کره) | ۱۷۳٬۳۱۶٬۲۹۹ بایت | −۱۷۵ کیلوبایت |

این عدد صادقانه است: **حجم APK مسئلهٔ UI نیست.** آرتیفکت را
`ca.psiphon.aar` با ۶۶ مگابایت و پشتهٔ کامل media3/ExoPlayer که ماژول
`:browser` می‌آورد تعیین می‌کند، نه کد رابط کاربری. هیچ مقدار کار روی UI
این را جابه‌جا نمی‌کند، و حذف آن دو یعنی حذف قابلیت — که بدون دستور صریح
انجام نمی‌دهم.

**دیباگ در برابر ریلیز:** APK دیباگ بزرگ‌تر است چون R8/ProGuard اجرا نمی‌شود
(کد مرده و کلاس‌های بی‌استفاده حذف نمی‌شوند)، منابع کوچک نمی‌شوند، اطلاعات
دیباگ و `debuggable=true` داخلش می‌ماند، و هر چهار ABI بومی کنار هم بسته
می‌شوند. ریلیز با کوچک‌سازی و تفکیک ABI به‌طور معمول چند برابر کوچک‌تر است.

## ۸. چیزهایی که ادعا نمی‌کنم

- **سرعت:** هیچ بهبود سرعتی را بدون اندازه‌گیری ادعا نمی‌کنم. چیزی که
  می‌توانم با شواهد کد بگویم این است: انیمیشن دائمی کره حذف شده، مقدارهای
  انیمیشن جدید فقط داخل لامبدای رسم خوانده می‌شوند، و صفحهٔ خانهٔ بی‌کار
  هیچ انیمیشنی اجرا نمی‌کند. اندازه‌گیری واقعی فریم/حافظه روی گوشی باید روی
  دستگاه انجام شود؛ محیط CI صفحه‌نمایش ندارد.
- **آزمون دستی روی گوشی:** انجام نشده. تنها چیزی که تأیید شده کامپایل‌شدن و
  گذشتن تست‌های واحد در CI است.
