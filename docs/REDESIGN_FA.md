# بازطراحی کامل UI/UX قاجار VPN

این سند مرجع طراحی است: ساختار صفحه‌ها، جای هر قابلیت، کدهای رنگ و ساختار تم،
و کارهایی که انجام نشده و دلیلش.

تنها چیزی که از هویت بصری قبلی نگه داشته شده **لوگوی قاجار VPN**
(`GhajarWordmark`) است. بقیهٔ ساختار از صفر ساخته شده.

---

## ۱. ساختار ناوبری

سه تب، نه بیشتر. ترتیب اعلان در کد از راست به چپ خوانده می‌شود، پس زیر RTL
نوار پایین این‌طور دیده می‌شود:

```
خانه  |  فروشگاه  |  تنظیمات
```

- `PAGE_HOME = 0` — صفحهٔ پیش‌فرض در هر اجرا و مقصد هر «بازگشت از همه‌جا»
- `PAGE_SHOP = 1`
- `PAGE_SETTINGS = 2`
- `PAGE_COUNT = 3`

SSH و دیباگر قبلاً تب بودند. همان صفحه‌ها با همان قابلیت‌ها الان از داخل
تنظیمات باز می‌شوند تا نوار سه‌تایی بماند.

## ۲. صفحهٔ خانه — دکمهٔ اتصال وسط

از بالا به پایین، همه وسط‌چین:

| ترتیب | جزء | کار |
|---|---|---|
| ۱ | `GhajarWordmark` | لوگو |
| ۲ | `StatusLine` | وضعیت واقعی تونل + دو خطای مهم: اینترنت دستگاه قطع، تونل برقرار ولی بدون داده |
| ۳ | `ConnectOrb` | دکمهٔ دایره‌ای ۲۳۲dp — وصل / قطع / لغو انتخاب خودکار |
| ۴ | `SessionLine` | مدت نشست جاری، فقط وقتی تونل بالاست |
| ۵ | `ServerPill` | سرور انتخاب‌شده، یک لمس تا انتخابگر |
| ۶ | سه `MetricTile` | سرعت دانلود + مجموع، سرعت آپلود + مجموع، تست تأخیر واقعی (قابل لمس) |
| ۷ | `ConnectionFacts` | آی‌پی عمومی اندازه‌گیری‌شده، کشور آن، پینگ زندهٔ سرور فعال |

نکته‌های فنی مهم:

- مقدارهای انیمیشن (`sweepState`, `breathState`) **فقط داخل لامبدای رسم
  `Canvas`** خوانده می‌شوند. کرهٔ قبلی همین را رعایت نمی‌کرد و باعث می‌شد کل
  زیردرخت هر فریم recompose شود.
- ستون وقتی جا شود وسط‌چین می‌ماند و وقتی جا نشود اسکرول می‌کند
  (`BoxWithConstraints` + `heightIn(min = maxHeight)` + `verticalScroll`)، پس
  صفحهٔ کوتاه یا فونت بزرگ سیستم هیچ‌وقت چیزی را نمی‌برد.
- هالهٔ نورانی فقط در حالت متصل کشیده می‌شود؛ صفحهٔ بی‌کار هیچ انیمیشنی ندارد.

## ۳. جای هر قابلیت بعد از بازطراحی

### قابلیت‌هایی که از خانه جابه‌جا شدند

| قابلیت قبلی | کجا بود | الان کجاست |
|---|---|---|
| وصل شدن | نوار تمام‌عرض پایین کارت | `ConnectOrb` وسط صفحه |
| قطع کردن | همان نوار | همان دکمه (آیکون و متن عوض می‌شود) |
| لغو انتخاب خودکار سریع‌ترین | همان نوار | همان دکمه |
| انتخاب/تغییر سرور | `GhajarSelectedServerCard` | `ServerPill` زیر دکمه |
| نام پاک‌سازی‌شدهٔ کانفیگ | همان کارت | `ServerPill` (`BrandConfig.sanitizePublicText`) |
| مخفی‌ماندن اندپوینت کانفیگ قفل‌شده | همان کارت | `ServerPill` |
| «موتور داخلی» برای aether/tor | همان کارت | `ServerPill` |
| راهنمای OpenVPN وقتی سروری انتخاب نشده | همان کارت | خط راهنما زیر `ServerPill` |
| سرعت و مجموع دانلود/آپلود | `StatBox` | `MetricTile` |
| تست تأخیر واقعی | دکمهٔ کنار `StatBox` | کاشی تأخیر (لمس = تست) |
| تایمر نشست | داخل `ConnectionHub` | `SessionLine` |
| آی‌پی / کشور / پینگ | `HubFact` داخل `ConnectionHub` | `ConnectionFacts` |
| رنگ خطای آفلاین و تونل مرده | نوار اتصال | `ConnectOrb` + `StatusLine` |

### تنظیمات (دسته‌بندی‌شده)

| دسته | ورودی‌ها |
|---|---|
| اتصال و سرورها | تنظیمات اتصال، ابزارها |
| عیب‌یابی و شبکه | دیباگر، رادار شبکه، SSH |
| مصرف داده | مصرف داده |
| برنامه | ظاهر برنامه، اعلان‌ها، درباره |
| داده‌های تو | پشتیبان‌گیری و بازیابی |

### ابزارها (دسته‌بندی‌شده)

| دسته | ورودی‌ها |
|---|---|
| اشتراک‌گذاری و تاریخچه | اشتراک‌گذاری VPN، تاریخچهٔ اتصال، لاگ و اشکال‌زدایی |
| اندازه‌گیری و تست | تست پایداری، بررسی میزبان، اسکن IP پاک |
| حریم خصوصی و مسیردهی | مسدودسازی تبلیغ (+ زیرتنظیم همیشه‌روشن)، مسیردهی پیازی، اتصال هوشمند |

### جابه‌جایی‌های دیگر

| قابلیت | قبلاً | الان |
|---|---|---|
| تنظیمات اعلان | بلوکی داخل بخش سوم فروشگاه | صفحهٔ «اعلان‌ها» در تنظیمات → برنامه |
| SSH | تب سطح‌اول | تنظیمات → عیب‌یابی و شبکه |
| دیباگر کانفیگ | تب سطح‌اول | تنظیمات → عیب‌یابی و شبکه |

هیچ قابلیتی حذف نشده و هیچ‌کدام تزئینی نشده. منطق اتصال، پروتکل‌ها، API
فروشگاه، پرداخت و بکاپ دست‌نخورده است.

## ۴. سیستم طراحی

همه‌چیز در `GhajarDesign.kt`. کامپوننت‌ها هیچ‌وقت رنگ عددی ندارند — بیرون از
این فایل و `Flagcolors.kt` (که رنگ پرچم ملی است، یعنی داده نه تم) هیچ فایلی
`Color(0x...)` ندارد.

### توکن‌های رنگ

`GhajarPalette` این‌ها را دارد: سطح‌ها (`background`, `surface`, `card`,
`secondaryCard`)، برند (`primary`, `premium`, `highlight`, `successGlow`)،
متن (`textPrimary`, `textSecondary`, `textMuted`)، خط (`border`,
`borderStrong`)، حالت‌ها (`error`, `onError`, `errorSurface`, `warning`,
`good`, `info`, `accentAlt`)، داده‌نما (`chart`, `neutralBar`)، و
(`disabled`, `onDisabled`, `scrim`).

معنی سه توکن که راحت اشتباه می‌شوند:

- `primary` = رنگ برند برای کارهای اصلی
- `good` = نتیجهٔ اندازه‌گیری سالم (پینگ سریع، تست موفق) — جدا از برند
- `successGlow` = فقط هالهٔ حالت «متصل»

### Premium Green Dark (پیش‌فرض نصب اول)

| نقش | کد |
|---|---|
| Background | `#050807` |
| Surface | `#0B1512` |
| Card | `#101816` |
| SecondaryCard | `#14231F` |
| PrimaryGreen | `#00A86B` |
| PremiumGreen | `#00B978` |
| HighlightGreen | `#24D98B` |
| SuccessGlow | `#0CE6A0` |

این هشت مقدار در `object GhajarBrand` یک‌جا تعریف شده‌اند؛ تم‌ها به آن‌ها
ارجاع می‌دهند و کامپوننت‌ها هیچ‌وقت.

### تم‌ها

چهار پالتهٔ کامل و مستقل، به‌علاوهٔ پیروی از سیستم:

1. `PREMIUM_GREEN_DARK` — پیش‌فرض نصب اول
2. `PREMIUM_GREEN_LIGHT` — سبزها تیره‌تر شده‌اند تا روی سفید کنتراست AA بدهند
3. `MIDNIGHT_BLUE`
4. `GRAPHITE_GOLD`
5. `SYSTEM` — بین دو پالتهٔ Premium Green سوئیچ می‌کند، پس پیروی از سیستم
   هویت برند را از دست نمی‌دهد

انتخاب در «تنظیمات → برنامه → ظاهر برنامه» است، در `ConfigStore` زیر کلید
`ui_theme` ذخیره می‌شود، از `ThemeMode` قبلی مهاجرت داده می‌شود، و فوراً
همه‌جا اعمال می‌شود.

### اضافه کردن تم جدید (سه قدم)

1. یک مقدار به `GhajarThemeId` اضافه کن (اسم را عوض نکن — اسم ذخیره می‌شود).
2. یک `GhajarPalette` کامل بساز؛ کامپایلر تا هر ۲۸ توکن پر نشود اجازه نمی‌دهد،
   پس تم نیمه‌کاره ممکن نیست.
3. در `GhajarPalettes` و `ghajarPaletteFor()` ثبتش کن.

هیچ صفحه‌ای لازم نیست عوض شود: `toColorScheme()` هر پالت را روی
Material 3 تصویر می‌کند، پس صفحه‌هایی که با `MaterialTheme.colorScheme`
نوشته شده‌اند هم خودکار تم فعال را می‌گیرند.

### فاصله، شعاع، حرکت

- `GhajarSpacing`: xs 4 · sm 8 · md 12 · lg 16 · xl 24 · xxl 32
- `GhajarRadius`: sm 10 · md 16 · lg 22 · xl 28 · pill 999
- `GhajarMotion`: Fast 140 · Base 220 · Slow 320 میلی‌ثانیه

### کامپوننت‌های مشترک

- `GhajarCard` (`GhajarCards.kt`) — **تنها تعریف کارت**: سطح کارت تم، خط مویی،
  شعاع md، بدون سایه. پارامتر `accent` فقط خط مویی را به رنگ حالت عوض می‌کند،
  پس کارت «در انتظار» شکلش عوض نمی‌شود.
- `SettingsHubCard`, `SettingsGroup`, `SettingsSectionTitle`, `GlassDialog`,
  `MetricTile`, `StatusLine`, `ServerPill`, `ConnectOrb`

### یک استثنای مستند

`object GhajarFixed` — QR باید با دوربین خوانده شود، پس جفت کنتراست ثابت دارد.
اگر تم را دنبال می‌کرد، در پالتهٔ روشن غیرقابل‌اسکن می‌شد.

## ۵. پنجره‌های غیر-Compose

دو پنجره از View ساخته شده‌اند (میزبان‌های WebView) و نمی‌توانند
`CompositionLocal` بخوانند، پس تا این بازطراحی با سرمه‌ای قدیمی `#071B2E`
رنگ می‌شدند:

- `GhajarStoreWebActivity` (پنل کامل فروشگاه)
- `SecurePaymentActivity` (مرورگر پرداخت امن)

تابع `ghajarPaletteFor(context)` همان تم ذخیره‌شده را بدون Compose حل می‌کند.
هر دو الان نوار وضعیت، نوار ناوبری، ظرف و پس‌زمینهٔ WebView را از پالتهٔ فعال
می‌گیرند و روشن/تاریک بودن آیکون‌های نوار وضعیت را از `palette.dark`
می‌خوانند.

**فلاش سفید هنگام اجرا:** پس‌زمینهٔ پنجره پیش از اجرای Compose توسط پلتفرم
کشیده می‌شود و روی پیش‌فرض Material Light بود، پس هر اجرای سرد یک فلاش سفید
داشت. الان به بوم برند اشاره می‌کند (`values-night/` نسخهٔ تاریک را دارد).

## ۷. حجم APK — عدد واقعی

از آرتیفکت‌های دیباگ CI، برای بخش UI این مأموریت:

| بیلد | حجم APK دیباگ | تغییر |
|---|---|---|
| CI 121 (قبل از حذف کره) | ۱۷۳٬۴۹۵٬۰۵۷ بایت | — |
| CI 123 (بعد از حذف ۱٬۷۵۳ خط کد کره) | ۱۷۳٬۳۱۶٬۲۹۹ بایت | −۱۷۵ کیلوبایت |

این عدد صادقانه است: **حجم APK مسئلهٔ UI نیست.** آرتیفکت را
`ca.psiphon.aar` با ۶۶ مگابایت و پشتهٔ کامل media3/ExoPlayer که ماژول
`:browser` می‌آورد تعیین می‌کند، نه کد رابط کاربری. هیچ مقدار کار روی UI
این را جابه‌جا نمی‌کند، و حذف آن دو یعنی حذف قابلیت — که بدون دستور صریح
انجام نمی‌دهم.

**دیباگ در برابر ریلیز:** APK دیباگ بزرگ‌تر است چون R8/ProGuard اجرا نمی‌شود
(کد مرده و کلاس‌های بی‌استفاده حذف نمی‌شوند)، منابع کوچک نمی‌شوند، اطلاعات
دیباگ و `debuggable=true` داخلش می‌ماند، و هر چهار ABI بومی کنار هم بسته
می‌شوند. ریلیز با کوچک‌سازی و تفکیک ABI به‌طور معمول چند برابر کوچک‌تر است.

## ۸. چیزهایی که ادعا نمی‌کنم

- **سرعت:** هیچ بهبود سرعتی را بدون اندازه‌گیری ادعا نمی‌کنم. چیزی که
  می‌توانم با شواهد کد بگویم این است: انیمیشن دائمی کره حذف شده، مقدارهای
  انیمیشن جدید فقط داخل لامبدای رسم خوانده می‌شوند، و صفحهٔ خانهٔ بی‌کار
  هیچ انیمیشنی اجرا نمی‌کند. اندازه‌گیری واقعی فریم/حافظه روی گوشی باید روی
  دستگاه انجام شود؛ محیط CI صفحه‌نمایش ندارد.
- **آزمون دستی روی گوشی:** انجام نشده. تنها چیزی که تأیید شده کامپایل‌شدن و
  گذشتن تست‌های واحد در CI است.
