# اصلاح پرداخت و تحویل ربات قاجار ۳.۲

پچ `0001-fix-bot-refund-failed-delivery-exactly-once.patch` فقط روی فایل‌های کدِ
نسخهٔ `Ghajarvpnbot3.2.zip` اعمال می‌شود و هیچ توکن، تنظیم محرمانه یا فایل کاربری
را وارد مخزن نمی‌کند.

این اصلاح دو خرابی مرتبط را پوشش می‌دهد:

- وابستگی `ManagePanel` پیش از ساخت یا تمدید سرویس به‌صورت امن آماده می‌شود؛ در
  نتیجه مسیر `Call to a member function createUser() on null` دیگر بدون جبران
  رها نمی‌شود.
- اگر پرداخت واقعاً تأیید شده باشد ولی تحویل سرویس شکست بخورد، مبلغ همان سفارش
  دقیقاً یک‌بار به کیف پول کاربر برمی‌گردد. وب‌هوک یا استعلام تکراری نمی‌تواند
  مبلغ را دوباره شارژ کند.

## روش اعمال

ابتدا از فایل‌ها و پایگاه‌داده نسخهٔ پشتیبان بگیرید، سپس در ریشهٔ سورس استخراج‌شدهٔ
ربات ۳.۲ اجرا کنید:

```bash
git apply --check /path/to/0001-fix-bot-refund-failed-delivery-exactly-once.patch
git apply /path/to/0001-fix-bot-refund-failed-delivery-exactly-once.patch
node tests/static_sanity.mjs
```

پچ ستون‌های وضعیت تحویل را به تعریف جدول اضافه می‌کند و در زمان اجرا نیز نبودن
آن‌ها را به‌شکل سازگار اصلاح می‌کند. بعد از استقرار، یک پرداخت آزمایشی در محیط
غیرواقعی و یک وب‌هوک تکراری را بررسی کنید: خروجی باید یا «سرویس تحویل شد» باشد یا
«مبلغ یک‌بار به کیف پول برگشت»؛ هیچ سفارش پرداخت‌شده‌ای نباید بین این دو حالت
بی‌سرانجام بماند.
